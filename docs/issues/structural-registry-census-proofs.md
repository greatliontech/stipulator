# Qualify source/record census proofs for the activated Cerebro registries

Lands: tooling-redesign 5.6, before Cerebro C.0.2/14.3 accepts the activated
generated-home, owner-route, fact-class-registry and registry-projections
contracts. This is a triggered consumer prerequisite, not an indefinite deferral
or authorization to extend the current linker-selection change set.

The installed Go proof classifier recognizes only direct calls to the five
`stipulate/structural` assertions: ImportAllowlist, NoImport, Implements,
ExportedData and FunctionSignature. They inspect import edges or type shapes;
they cannot establish registry record values, complete generated-file ownership,
single declaration ownership or the consumers' derivation from that owner.
A custom AST census or go/analysis analyzer has no supported proof-registration
surface. A `proves` binding refuses its example classification; adding an
incidental import assertion would launder the class without proving the claim.

Concrete counterexamples leave all five existing assertion surfaces unchanged:
move a generated output to another import-legal home; duplicate a route pair;
copy a descriptor vocabulary into a same-package classifier; or add a hand-kept
projection switch. The affected structural requirements can all become false.
Invariant registry-drift and declaration-admission instead admit genuine property
witnesses; this issue does not promote their evidence requirement to analyzer-only.

The minimum missing semantic capability is a qualified closed-world typed
source/record census: exact keyed uniqueness, allowed record arms, total reference
joins, bidirectional file/output correspondence and authoritative declaration/use
relations. The concrete population is genspec routes/output roles, descriptor
construction and consumers, actual generated artifacts/writers, and citation-usage
field initialization and compile references. It must reject incomplete discovery,
load errors and unsupported indirection; no arbitrary Boolean callback or empty
caller list can establish a complete population. Bounded admission-before-builder
and validation-before-writer paths require real analysis, not signature assertions.

Keep domain ownership judgments and the qualified analyzer in Cerebro. The tool
needs an independently reviewed native analyzer execution/recognition boundary,
with exact analyzed subject/population attribution and existing observation and
freshness safeguards. Existing AST/census judges are reusable input, not already
complete proof. Determine that narrow runner/admission contract before adding an
API; do not introduce a generic plugin framework or encode Cerebro's registry as
a second tool-owned list. A closed built-in relation assertion is an alternative
only if it actually expresses these private registry/use relations without a
second source or broader extraction framework.

Acceptance requires real fault-bearing fixture/property cases and named probes
for omitted records/files, duplicate owners, parallel enumerations, missed fields,
unsupported constructions and skipped validation paths; successful execution of
the whole-population analyzer; and native proof classification of that execution.
Do not weaken structural kinds, use token NoImport proofs, blanket-pin existing
records or treat the linker feature as completion. Until separately authorized
and qualified, the affected Cerebro structural acceptance remains blocked under
its existing delivery rules; independent work can continue.
