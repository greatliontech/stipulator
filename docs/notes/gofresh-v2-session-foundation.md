## Key Architectural & Soundness Derivations

- **Purity-Asserted vs Mechanically Pure Observation Discipline (`REQ-purity-override`, `REQ-evidence-witness-freshness-inputs`)**:
  - Under `gofresh`'s `REQ-purity-override` (`guard-drift` and `producing-motion`) and `stipulator`'s `REQ-evidence-witness-freshness-inputs` (`outcome_test.go:71-93`, `derive_publish_test.go:646-725`), purity assertions (`//gofresh:pure` or `assume_pure: true`) suppress inferred unverifiability while keeping hashable `IdentityObservation` drift guards over files/env actually read (`Capture: logPath` via `BeginIdentity`), whereas Tier-1 mechanically pure subjects (`NeedsObservation == false` && `PurityAssertion == ""`) provably read zero files/env and omit `RuntimeInputs`/`RuntimeDigest` (`Capture: ""` in Chunk 3). Admitting `RuntimeInputs == "" && RuntimeDigest == ""` in `witnesscache` when `ObservationProof == {}` satisfies both Tier-1 pure witness records and synthetic pure test fixtures without `MergeObservations`.
- **Single-Snapshot `PackageExecution` + `SingleSubjectExecution` Partitioning (`native.go`)**:
  - Constructing one `gofresh.Session` (`Execution: gofresh.PackageExecution`) and one `Snapshot` (`CodeResult`), then calling `snapshot.WithExecution(gofresh.SingleSubjectExecution)`, eliminates the second `gofresh.Session`, the second 2-pass `go list` + typed `go/packages` load, and the second SSA/RTA `Prover` build in `captureNativeGeneration`.
  - Checking `SharedDynamicStateCause` via `BindRuntime` (`CodeResult`, zero spawns) + `BeginCheck` -> `CheckBatch` -> `Abort` evaluates `decide` + `judgmentFor` purely in memory over the newly observed 2-pass `Snapshot` without paying extra closing re-observation spawns.
