# Chunk 3 Working Notes: Unified Package-Slot Witness Execution, `ExcludedEnv`, Reduced-Batch Isolation & Core/Leaf Policy Split

## Governing Contracts & Invariants

1. **Publication-Slot Exclusion (`REQ-policy-cancellation-publication-slot`, `REQ-policy-explicit-time-bounds`):**
   - `Unit.Close` (`finishNativeRun`) performs runtime-input re-hashing, classification-root probing, and source-view validation; it MUST run after `gate.release()` under the caller's context (`ctx`), never inside `inSlot` under the invocation envelope (`invCtx`) or while holding a spawn slot.
   - **Diagnosis of prior bottleneck:** Both `executeInvocationPrepared` (`execute.go:371-393`) and `executeSelectionObserved` (`selection.go:287-302`) duplicated `inSlot`/`afterSlot` lifecycle closures AND wrapped `finishNativeRun` inside the invocation-wide `mu.Lock()`. Because `gofresh.Unit` instances are independent per attempt and `packageLeg.validateInputs` owns its own `l.preparation` mutex, holding `mu.Lock()` across `finishNativeRun` serialized multi-GiB `testlog` parsing across all concurrent packages and retained every queued package's `/tmp/stipulator-testlog-*.txt` on disk.
   - **Rejected dead end:** Moving healthy `finishNativeRun` (`Unit.Close`) into `inSlot` would violate `REQ-policy-cancellation-publication-slot` (holding a spawn slot during validation/closing and spending `invCtx` budget before subsequent solo spawns) and break `beforePackagePublishForTest` (`TestExecutedRecordDropsWhenItsInputMovesBeforeItsPublish`, `TestWitnessBehindAPipeHold`, `TestRuntimeMovementAllowsLaterPackagePublication`).
   - **Causal design:**
     - Consolidate `executeInvocationPrepared` and `executeSelectionObserved` onto one shared `executePackageUnits` lifecycle driver (`packageExecutionPlan` + `runFollowupAttempt` + `releasePackageUnits`).
     - On `ExecuteSelection` (`discardUnhealthy: true`, where `REQ-evidence-witness-freshness-isolation` guarantees a red process grants zero green witness evidence while `ExecuteInvocation` retains `CompletedObservation` on ordinary failures per `REQ-evidence-outcome-premises` / `TestOrdinarilyFailedProcessHasIdentityGuardsButNoWitness`), abort `a.unit` and unlink `a.logPath` **immediately inside `inSlot`** whenever an attempt finishes with `disposition != HEALTHY`, freeing multi-GiB red-batch `testlog`s before isolation spawns and skipping `Unit.Close` in `afterSlot`.
     - In `afterSlot` (after `gate.release()`), run `finishNativeRun` **outside `mu.Lock()`** when `beforePackagePublishForTest == nil` so each finished package closes and unlinks its `testlog` concurrently and immediately, acquiring `mu.Lock()` only around `firstErr` and serialized `onPackage(unit)` (while keeping `beforePackagePublishForTest` + `finishNativeRun` + `onPackage` atomic under `mu.Lock()` when `beforePackagePublishForTest != nil`).

2. **Native Unit Preparation, Unwitnessed `testlog` Elision, `ExcludedEnv` & Coherent `MovedInputs` (`REQ-evidence-witness-freshness-bracket`, `REQ-evidence-outcome-premises`, `REQ-evidence-witness-freshness-diagnosable`):**
   - **Rejected dead end:** Omitting `Capture: logPath` (`Capture: ""`) on witnessed mechanically pure or purity-asserted runs in `stipulator` would violate `REQ-evidence-witness-freshness-bracket` ("Each producing process's completed observation MUST be sealed against an observation bracket captured before the process spawns") and `REQ-evidence-outcome-premises` ("Missing outcome support retains identity-only input guards"), breaking `TestWitnessEngineAttestsThePackageProcessModel`, `TestDeriveWitnessesPublishesNativeFingerprints`, `TestGoExecuteObservationOwnership`, `TestRootsProbeRunsThroughTheProbeRunnerOncePerPackage`, and `TestLinkerExecutionAndFreshnessUseActualAssignments`. `gofresh` `Unit.Register` already skips SSA/RTA `prepareOutcomeSupport` automatically whenever `!binding.NeedsObservation(subjects)` (source-supported or purity-asserted) while sealing lightweight identity-only input guards (`IdentityObservation`).
   - **Causal design:**
     - Skip `os.CreateTemp("", "stipulator-testlog-*.txt")` and `-test.testlogfile` completely (`logPath = ""`) whenever `leg == nil` (unwitnessed `multiIneligible` shadow legs, `proofs == nil` runs, or absent `executionLegs`).
     - In `prepareNativeAttempt`, select `binding.Begin(subjects[0])` for single-subject executions (`len(subjects) == 1`) and `binding.BeginPackage(subjects)` for multi-subject executions, query `binding.NeedsObservation(subjects)` for diagnostic tracing (`prepare_native_attempt`), and pass `ExcludedEnv: runnerExcludedEnv(runtime)` (`[]string{"GOCOVERDIR"}` when `runtime.CoverageDir != ""`) so ephemeral per-attempt coverage directories never taint `os.Environ()`-reading witnesses under `-cover`.
     - Enrich `nativeCloseRefusal` (`*gofresh.RuntimeInputSpanError.MovedInputs`) and `verdictReasonWithMovers` (`CheckedCandidate.MovedInputs`) so post-run producing-span and serving/revalidation drift reasons always carry coherent `MovedInputs` attribution without duplicating `(moved: ...)` suffixes.

3. **Reduced-Batch `deniedTests` Isolation Before Solo Fallback (`REQ-evidence-witness-freshness-isolation`):**
   - When `ExecuteSelection`'s initial batch fails cleanly on specific top-level test(s) (`unit.run.disposition == HEALTH_DISPOSITION_TEST_FAILED`, `len(unit.run.aborted) == 0`, `hasFailedTopLevel(&unit.run)`), leaving `len(batchDenied) >= 2` batch-eligible denied tests, run **at most one reduced-batch attempt** (`selection = batchDenied`, `soloTest = ""`) before per-test solo fallback:
     - If the reduced batch disposes `HEALTHY`, all `len(batchDenied)` witnesses recover their green outcomes and publish valid `witnesscache` records in **1 process** instead of `N` sequential processes.
     - If the reduced batch itself fails, aborts, or times out, record its outcomes/diagnostics on `unit.solos`, narrow `denied = deniedTests(&reduced, batchDenied)` (excluding any newly failed top-level tests), and fall back to one-by-one solo isolation for the remainder (never looping a second reduced batch).

4. **Core/Leaf Policy Split & Width/Timing-Sensitive Test Fixes (`.stipulator/policy.textproto`):**
   - Split `.stipulator/policy.textproto`'s 45-package root-module `race` invocation into `race:core` (`./internal/backends/golang`, `./internal/cmd` -> `SpawnBound = 2`, `GOMAXPROCS = 16` on 32 cores) and `race:leaf` (remaining 43 root-module packages), retaining `race:stipulate` and `race:stipulate/structural` in strict ASCII byte order (`race:core < race:leaf < race:stipulate < race:stipulate/structural`) with exact `PartitionReports` conservation (`0` omissions, `0` duplicates).
   - Fix all 5 remaining width/timing-sensitive tests in `internal/backends/golang`:
     - `TestServedRecordRevalidatesAfterTheRunsExecutions` (`freshness_test.go`): enforce `GOMAXPROCS >= 4` so the inner 2-package barrier run allocates 2 concurrent slots even under parent `GOMAXPROCS=2`.
     - `TestGoScopedAllocationWarmWidthMovement` & `TestGoScopedAllocationWarmUnobservedWidthMovement` (`allocation_integration_test.go`): set `procs := max(4, runtime.GOMAXPROCS(0))` instead of `t.Skip` when `< 4`.
     - `TestAdmissionsOfOneProcessShareTheHostGate` (`admission_test.go`): replace `time.After(100ms)`/`150ms` sleeps with deterministic `waitGateParked(t, want)` barriers and drain cancelled `alphaSecond`/`betaSecond` goroutines before `freshGate(t)`.
     - `TestGoExecuteEnvelopeTimeoutNamesAbortedTests` (`execute_unix_test.go`): pre-discover `n` (`DiscoverInvocation`) outside the timeout window and widen `n.Timeout` to `5s` so warm `go test -c` + `-race` binary startup reliably reaches `=== RUN   TestHang` under narrow width.
